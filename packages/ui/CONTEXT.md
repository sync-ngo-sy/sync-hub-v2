# Design System

The shared visual language of all three portals: the design tokens and every component that
renders purely from props. Nothing in this context fetches data or knows the API exists.

## Language

**Token**:
A named CSS variable in the single global stylesheet that carries one visual decision —
a color, a radius, a type step. Components reference tokens, never raw values.
_Avoid_: Theme variable, style constant.

**Primitive**:
A component under `components/ui` originally generated by the shadcn CLI, now owned and
hand-edited like any of our code (ADR-0002); CLI regeneration is abandoned. The floor of
the system. The CLI has no recipe for every Base UI part, so the floor is not the whole
of what we build on Base UI: where the recipe is missing, the component is hand-written
as a Molecule instead.
_Avoid_: Base component, atom.

**Molecule**:
A hand-written shared component that renders from props, composed from Primitives and
Tokens (a data table, a stat card, an empty state) or, where no Primitive exists, from a
Base UI part directly (the combobox). Owned, linted, and tested like any of our code.
_Avoid_: Widget, composite.

**Status Mark**:
The rendering of a status: an 8px mark (filled for anything still in flight, a circle-x
icon for `rejected`/`withdrawn`, a hollow ring only for the general `waiting` tone) beside
a plain-text label. The only
way status appears anywhere; filled status pills do not exist (ADR-0003). Its eight
application tones are the `--status-*` tokens, 1:1 with the database enum — a teal-to-green
ramp separated by lightness and hue, plus amber for `reviewing` and blue for `new`
(ADR-0005). Everything else with a state — a Job, a CV, a Tracked link, a colleague's
access — takes one of the four general tones (`waiting`, `active`, `attention`, `ended`),
which say their state by mark shape and borrow no `--status-*` token, so the status
vocabulary stays exactly as long as the enum (ADR-0004). They take `--muted-foreground`,
`--accent-foreground`, or their own `--mark-*` token — `attention` has one, holding the
same amber as `--status-review` without depending on it.
_Avoid_: Chip, status pill, badge.

**Candidate Card**:
The summary block of a candidate's key facts — avatar, name, canonical role, headline,
email, phone, total years of experience, languages. It is the leading block in Recruiter
candidate views and also appears inside the Candidate Portal's profile editor. It owns the
name heading: level one when it is the page heading, level two when the surrounding page already
has one. It is deliberately louder than the cards under it (accent wash, accent ring, deeper
shadow). The avatar falls back to initials until an uploaded photo exists. A page whose facts are
not simply current may add a plain context label beside the name and a line under the facts saying
where they came from. Neither is a Status Mark or badge, and a card given neither claims nothing.
_Avoid_: Profile header, summary card.

**Promotion**:
The move of a component from one portal's feature into the Design System, permitted only
when a second consumer appears. Until then the component stays where it was born.
_Avoid_: Extraction, hoisting.
